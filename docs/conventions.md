# 코딩 규칙

Pullshot 코드를 쓰고 리뷰할 때 이 문서를 기준으로 삼습니다. 두 곳의 방식을 Swift에 맞게 옮겼습니다.

- 작성자가 전에 일한 팀의 코드 작성 원칙과 규칙입니다. 이름, 테스트, 오류, 커밋 방식이 여기서 왔습니다.
- Tethersnap(https://github.com/Luminoid/Tethersnap)의 SwiftLint, SwiftFormat, pre-commit 설정입니다. 린트와 포맷 규칙이 여기서 왔습니다.

둘이 부딪히면 앞의 것을 따릅니다. 줄 폭 120, 한국어 테스트 이름, 커밋 형식이 그렇게 정해졌습니다.

## 원칙

1. 코드가 곧 문서입니다. 읽기 쉬운 것을 가장 먼저 챙깁니다.
2. 쓴 코드는 모두 관리할 짐입니다. 가장 적은 코드로 만들고, 기본값과 같은 인자는 적지 않습니다.
3. 이름은 구현이 아니라 동작과 도메인을 드러냅니다.
4. 테스트 제목이 구현을 따라가면 구현이 바뀔 때마다 테스트도 바뀝니다. 테스트 제목은 도메인 언어로 씁니다.
5. 코드 스멜은 보는 즉시 고칩니다. 미룰수록 커집니다.
6. 코드도 글처럼 문단을 나눕니다. 빈 줄은 생각이 바뀌는 곳에만 둡니다. 선언, 실행, 반환처럼 문법이 바뀐다는 이유로는 띄우지 않습니다.

## 이름

- Bool은 뜻에 맞는 접두사를 붙입니다. 상태와 속성은 `is`, 가진 것은 `has`, 능력은 `can`, 의도는 `should`입니다(`isOpen`, `hasThumbnail`).
- 한 시점에 일어난 일은 과거분사로 씁니다(`opened`, `cancelled`).
- 함수가 아닌 값은 명사(구)로 짓습니다.
- 한 번만 쓰는 값은 바로 씁니다. 이름이 뜻을 더하거나, 줄이 너무 길어지거나, 반복 안에서 매번 다시 계산될 때만 변수로 둡니다.
- 표준이나 기기가 정한 이름은 그대로 씁니다(PTP의 `GetObjectHandles`, `StorageID`).
- 용어와 코드 이름의 짝은 `docs/glossary.md`에 둡니다.

## 제어 흐름

- 같은 열거값으로 가를 때만 `switch`를 씁니다. 범위 비교, 복합 조건, 케이스 안의 추가 분기는 `if`로 씁니다.

## 오류

- PullshotKit은 도메인 오류(`SessionError`, `ConsoleAccessError` 등)를 그대로 던집니다. Kit 타입에는 사용자 문구를 두지 않습니다.
- 사용자 문구로 바꾸는 일은 가장자리 한 곳에서 합니다. CLI는 `ErrorMessages`, 앱은 `AppErrorMessages`와 문자열 표입니다. 같은 문구가 필요해도 각자 둡니다.

## 테스트

- Swift Testing을 씁니다. 검증은 `#expect`와 `#require`입니다.
- 타입마다 `@Suite("<타입> 테스트")`를 두고, 그 안에 동작별 `@Suite("<동작>")`을 둡니다.
- 테스트 이름은 한국어 도메인 문장으로 씁니다. "~하면 ~한다"처럼 조건과 결과를 적습니다.

  ```swift
  @Suite("Session 테스트")
  struct SessionTests {
      @Suite("세션 열기")
      struct Opening {
          @Test func `세션 없이 기기 정보를 거부하면 세션 안에서 다시 받는다`() throws { … }
      }
  }
  ```

- 기대값은 손으로 계산한 값을 적습니다. 테스트 대상 코드로 기대값을 만들지 않습니다.
- 테스트 데이터는 `<대상>Fixture(...)` 함수로 만들고, 기본값을 둬서 테스트마다 다른 값만 적습니다.
- 실기기 덤프(`LocalFixtures/`)는 기기 일련번호와 사용자 캡처가 들어 있어 커밋하지 않습니다.

## 주석과 로그

- 주석은 무엇이 아니라 왜를 적습니다. 실기기에서 확인한 사실은 날짜와 펌웨어를 함께 적습니다(예: "2026-11-15, 펌웨어 23.5.0").
- 선언 앞 설명은 `///`로 씁니다.
- 로그는 `os.Logger`(subsystem `com.parkgiraffe.Pullshot`)를 씁니다. 파일 이름, 게임 이름, 경로, 일련번호는 `privacy: .private`로 남깁니다.

## 린트와 포맷

- SwiftLint `--strict`와 SwiftFormat `--lint`를 `make check`와 pre-commit 훅이 강제합니다. 처음 한 번 `make setup-hooks`를 실행합니다.
- 줄 폭은 120입니다. 컬렉션 리터럴은 마지막 원소 뒤에 쉼표를 붙이고, 함수 호출에는 붙이지 않습니다.
- `identifier_name` 규칙은 끕니다. 한국어 테스트 이름 때문입니다.

## 의존성

- PullshotKit은 외부 패키지를 쓰지 않습니다. CLI만 swift-argument-parser를 씁니다.
- 새 패키지는 넣기 전에 제안하고 승인을 받습니다. 이미 있는 코드를 패키지로 바꿀 때도 같습니다.

## 커밋

- 제목은 `{대상} {액션}` 꼴의 한국어 명사형입니다(`PTP 컨테이너 추가`, `Session 재연결 순서 수정`).
- 72자를 넘지 않고, 마침표로 끝내지 않습니다. 식별자는 표기 그대로 쓰고, 여럿이면 쉼표로 나눕니다.
- 제목으로 충분하면 본문은 생략합니다. 본문은 하십시오체로 무엇을, 왜 바꿨는지 적습니다.
- Claude나 다른 도구를 공동 작성자로 적지 않습니다.
