# 실기기 기록

2026-11-15에 Nintendo Switch 2(펌웨어 23.5.0)를 MacBook Pro(Mac15,6, macOS 26.5)에 USB-C 데이터 케이블로 연결해 확인한 사실입니다.
2단계(라이브러리)와 3단계(앱) 계획의 입력입니다. 기기 일련번호와 캡처 원본은 이 문서와 리포에 남기지 않습니다.
덤프 원본은 커밋하지 않는 `LocalFixtures/switch2-23.5.0/`에 있고, `LocalFixtureTests`가 있을 때만 재생합니다.

Nintendo Switch(1세대)는 기기가 없어 확인하지 못했습니다. 제품 ID 0x201D는 Tethersnap 기록을 따른 것이고, 앱에서는 실험적 지원으로 표시합니다.

## 기기 정보

| 항목 | 값 |
|---|---|
| 제조사, 모델 | Nintendo, Nintendo Switch 2 |
| PTP 버전 | 100 |
| 지원 명령 | 0x1001 ~ 0x100A 10개뿐입니다. DeleteObject(0x100B)가 없어 기기의 캡처를 지울 수 없습니다. |
| 저장소 | "Album" 하나입니다. 용량과 남은 공간은 모두 0xFF로 와서 알 수 없습니다. |
| 저장소 ID | 세션마다 바뀝니다(0x00060001, 0x00070001, 0x00090001). 기록의 키로 쓰면 안 됩니다. |
| 일련번호 | 여러 세션과 USB 리셋 뒤에도 같습니다. 기기를 구분하는 키로 쓸 수 있습니다. |

## USB 상태

| 상태 | VID:PID | 인터페이스 |
|---|---|---|
| PC로 복사 모드 | 0x057E:0x2061 | 사진 전송(클래스 6, 하위 1, 프로토콜 1) |
| 그 밖(대기) | 0x057E:0x2060 | HID만 있습니다. |

- IOKit 검색은 제조사 ID만 주면 아무것도 찾지 못합니다. 제품 ID 목록을 함께 줘야 합니다.
- USB 장치 리셋을 보내면 스위치가 PC로 복사 모드를 나가 0x2060으로 다시 붙습니다. 사용자가 본체에서 PC로 복사를 다시 켜야 하므로, 앱은 USB 리셋을 마지막 수단으로만 쓰고 그 뒤에 모드를 다시 켜 달라고 안내해야 합니다.
- 0x2060으로 붙어 있으면 "연결은 됐지만 PC로 복사 모드가 아님"으로 알아보고 안내할 수 있습니다.
- USB 리셋 뒤 사용자가 PC로 복사를 다시 켰을 때 같은 프로세스가 다시 연결하는 경로(사진 전송 인터페이스가 늦게 생기는 경우 5초 재시도)는 아직 실기기로 확인하지 못했습니다.

## 앨범 구조

- 루트 바로 아래가 게임 폴더이고, 캡처는 그 폴더 안에 있습니다. 더 깊은 폴더는 없었습니다.
- 한글 게임 이름이 그대로 옵니다(예: "파이어 엠블렘 만자천홍", "모여봐요 동물의 숲").
- 스위치에 "기타"라는 폴더가 실제로 있습니다. Pullshot이 게임 폴더 밖 캡처를 부르는 이름 "기타"와 겹치므로, 2단계에서 둘을 구분할지 정해야 합니다.
- 게임 폴더 12개에 캡처 3,082개(사진 2,902개, 영상 180개), 합계 약 6.9GB였습니다. 전체를 훑는 데 약 16초 걸립니다.

## 파일 이름과 메타데이터

- 이름 형식은 `YYYYMMDDhhmmss` + 두 자리 순번 + `_s` 또는 `_c` + 확장자입니다. 예를 들면 `2026010112000000_s.jpg`입니다.
  - 같은 초에 찍은 캡처는 순번으로 나뉩니다(`…0900_s.jpg`, `…0901_s.jpg`).
  - 개수는 `_s.jpg` 2,460개, `_c.jpg` 442개, `_s.mp4` 165개, `_c.mp4` 15개였습니다. `_s`와 `_c`가 무엇을 뜻하는지는 확인하지 못했습니다.
- ObjectInfo의 CaptureDate가 채워져 옵니다. 시간대 표기는 없으므로 본체의 지역 시각으로 읽습니다.
- 형식 코드는 사진 0x3801(EXIF JPEG), 영상 0xB982(MP4)입니다.
- GetThumb는 사진(약 19KB)과 영상(약 15KB) 모두 됩니다.

## 전송

- 데이터 단계에서 12바이트 헤더가 먼저 따로 오고, 본문은 그다음 읽기부터 옵니다.
- 받은 파일은 `list` 크기와 바이트 단위로 같았습니다. 영상(5,616,157바이트)은 8.3초, 트랙 2개로 재생되고, 사진은 1920×1080입니다.
- 45.1MB 영상 하나를 약 0.3초에 받습니다. 캡처 3,082개(약 6.9GB) 전체 받기는 훑기를 포함해 약 87초 걸렸고 실패는 없었습니다.
- 연결할 때마다 앞 연결이 남긴 바이트를 비우는 읽기가 한 번 시간 초과(0xE00002D6, 0.3초)로 끝납니다. 연결이 그만큼 늦어집니다.

## 다른 앱이 스위치를 쥔 경우

- Tethersnap 앱이 인터페이스를 쥐고 있으면 열기가 0xE00002C9로 실패합니다. IORegistry의 `UsbExclusiveOwner`가 "pid N, Tethersnap" 형식이라 쥔 앱 이름을 안내에 넣을 수 있습니다.
- 미리보기나 이미지 캡처 앱을 켜면 ptpcamerad가 스위치를 쥐고, 같은 0xE00002C9로 실패합니다. 그 앱을 끄면 풀렸습니다.
- 0xE00002C5(독점 접근)는 이번 확인에서 나오지 않았습니다.

## 세션이 남은 경우

`kill -9`처럼 세션을 닫지 못하고 끝난 프로세스가 있으면 스위치에 세션이 남습니다.

1. 세션 없는 GetDeviceInfo는 빈 데이터 단계와 0x2004로 답합니다.
2. OpenSession은 0x201E(이미 열림)로 거부됩니다.
3. 트랜잭션 ID 0으로 보낸 CloseSession도 0x2004로 거부됩니다.
4. PTP 장치 리셋(클래스 요청)은 멈춤(0xE0005000)으로 끝납니다.
5. 남은 수단인 USB 장치 리셋을 보내면 풀리지만, 스위치가 PC로 복사 모드를 나갑니다.

그래서 세션을 남기지 않는 것이 가장 중요합니다. 지금 코드는 취소와 오류 뒤에도 남은 데이터를 비우고 CloseSession을 보냅니다.
0x2004는 트랜잭션 ID가 틀렸다는 응답이므로, 마지막 트랜잭션 ID를 디스크에 남겨 두면 강제 종료 뒤에도 USB 리셋 없이 닫을 수 있을지 모릅니다. 아직 확인하지 않았습니다.

PC로 복사 모드를 껐다 다시 켠 스위치는 세션 없는 GetDeviceInfo를 받아 줬습니다. Tethersnap이 펌웨어 22.5.0에서 기록한 거부는 23.5.0에서 재현되지 않았지만, 코드는 거부에 대비한 경로를 유지합니다.

## 취소와 끊김

- 신호 처리기로 Ctrl-C를 받으면 진행 중인 USB 읽기가 0xE00002EB로 끊겨 세션이 어긋났습니다. 지금은 SIGINT를 무시하고 디스패치 소스로만 알아챕니다.
- 훑는 중 취소: 객체 사이에서 멈추고 세션을 닫습니다. 다음 연결이 리셋 없이 바로 열렸습니다.
- 받는 중 취소: 45.1MB 영상의 남은 데이터 단계를 끝까지 읽어 버리고 반쯤 받은 파일을 지운 뒤 세션을 닫습니다. 다음 연결이 리셋 없이 바로 열렸습니다.
- 받는 중 케이블 뽑기: 읽기가 0xE00002EB로 끝나고, 그 뒤 호출은 0x10000003으로 실패합니다. "스위치 연결이 끊겼습니다" 안내가 나오고, 반쯤 받은 파일(`.pullshot-partial`)은 남지 않았습니다.
  - `pull`은 첫 끊김에서 멈추고 "저장 1470개, 건너뜀 0개, 실패 1개"로 요약합니다. 시도하지 못한 나머지 캡처는 요약에 없습니다.
  - 케이블을 다시 꽂으면 스위치는 PC로 복사 모드를 그대로 유지합니다. 뽑을 때 열려 있던 세션도 남지 않아, 다음 연결이 세션 없는 GetDeviceInfo부터 리셋 없이 열렸습니다.

## 2단계 확인(2026-11-15)

옮긴 기록은 시험용 폴더(`--ledger-folder`)에 따로 두고 확인했습니다.

- 새 항목 받기: 캡처 13개짜리 게임에서 `pull --new`로 13개를 받았고, 두 번째 실행은 `저장 0개`였습니다. 받은 파일의 만든 날짜와 수정 날짜가 찍은 시각과 초까지 같습니다.
- 번호 붙여 내보내기: `001_20220909_153710.jpg`부터 찍은 순서로 붙었고, 빈 폴더에서는 `--dry-run` 미리보기와 실제 이름 13개가 모두 같았습니다. 영상도 같은 규칙(`004_….mp4`)을 따릅니다.
- 폴더에서 찾기: 받은 폴더로 찾자 13개를 기록했고, 그 캡처는 `list --new`에서 빠졌습니다. 없는 폴더를 주면 스위치에 연결하기 전에 멈추고 기록 파일도 만들지 않습니다.
- 미리보기 앱이 켜져 있으면 ptpcamerad가 인터페이스를 쥐어 0xE00002C9로 실패하고, 미리보기와 사진 앱을 닫으라는 안내가 나옵니다. 앱을 끄자 바로 연결됐습니다.
- 플레이 나누기: 60분 기준으로 캡처 2,625개짜리 게임이 플레이 29개로 나뉘었습니다. 사용자가 플레이별 보기는 필요 없다고 해 기능을 뺐고, 앱의 기본 보기는 최신순입니다.
- 모든 확인이 끝난 뒤에도 다음 연결이 USB 리셋 없이 열렸습니다.

## 2단계와 3단계에 넘길 것

- 옮긴 기록의 키는 일련번호와 파일 이름으로 정합니다. 저장소 ID와 객체 핸들은 세션마다 바뀌므로 쓰지 않습니다.
- 스위치의 "기타" 폴더와 게임 폴더 밖 캡처의 이름이 겹치지 않게 정합니다.
- 앱은 0x2060 상태를 보고 "PC로 복사를 켜 주세요"를 안내하고, USB 리셋을 했으면 그 사실과 할 일을 함께 알립니다.
- 앱이 강제 종료돼도 다음 실행이 USB 리셋까지 가지 않도록, 마지막 트랜잭션 ID를 남겨 닫는 방법을 실기기에서 확인합니다.
- 끊긴 뒤의 요약에 시도하지 못한 캡처 수를 함께 보여 줍니다.

## 3단계 임시 확인(실기기 없이, 2026-11-16)

스위치를 꽂을 수 없어, 3단계 계획의 실기기 확인(Task 13) 가운데 기기 없이 볼 수 있는 것만 Mac Studio(macOS 27.2)에서 먼저 확인했습니다.
앱은 `make app`으로 만든 릴리스 빌드를 데모 앨범(`-demoAlbum YES`)과 시험용 기록 폴더(`-ledgerFolder`, `-importFolder`)로 열었습니다.
이 Mac은 화면이 잠겨 있어 누르기와 키 입력이 앱에 닿지 않았습니다. 게임 범위, 고른 상태, 옮기기 진행과 결과, 처음 연결 질문은 커밋하지 않은 확인용 코드로 만들어 화면만 봤습니다.

### 확인한 것

- 연결 안내: 스위치 없이 열면 "스위치를 연결해 주세요"와 두 단계 안내가 나오고, 기기 칸은 "연결된 스위치 없음"입니다.
- 격자와 보기: 데모 캡처 60개가 최신순 격자로 나옵니다. 날짜 보기는 월 제목 아래 날마다 묶고, 날 제목에 찍은 시간대를 붙입니다.
- 영상 필터와 찾기 칸: 영상 필터는 영상 12개만 남기고 오른쪽 칸 수도 같이 바뀝니다. 게임 찾기 칸은 이름이 맞는 게임만 남기고, 맞는 게임이 없으면 "찾는 게임이 없습니다"를 보입니다.
- 크기 막대: 썸네일 크기 120에서 7열, 360에서 2열로 바뀝니다.
- 고르기: 8개를 고르면 칸마다 강조색 테두리와 체크가 붙고, 오른쪽 칸에 겹친 썸네일, "8개 고름", 사진과 영상 수, 크기, 찍은 때가 나옵니다.
  - 키보드 고르기는 직접 누르지 못해 `GridSelection` 단위 테스트(누르기, ⌘, ⇧, 화살표)가 통과하는 것만 확인했습니다.
- 가져오기와 내보내기 단추: 데모에서는 "새 항목 N개 가져오기"와 "내보내기"가 꺼져 있습니다. "게임 전체 내보내기"는 모두 고르기만 하므로 켜져 있습니다.
- 번호 붙이기 미리보기: 8개를 고르고 "찍은 순서대로 번호 붙이기"를 두면 가장 먼저 찍은 캡처부터 `001_YYYYMMDD_hhmmss`로 붙고, 영상은 `.mp4`를 그대로 씁니다. 6개부터는 앞 세 개와 마지막 하나 사이를 줄여 보입니다. 2단계 확인의 CLI 이름 규칙과 같습니다.
- 끝내기: 데모로 연 앱에 quit 이벤트를 보내자 0.16초 만에 끝났고, 미리 만들어 둔 미리보기 원본 폴더(`Pullshot-preview`)를 지웠습니다. 데모는 세션을 열지 않으므로 세션을 닫고 끝내는 경로(최대 10초 기다림)는 확인하지 못했습니다.
- CLI: 스위치 없이 `list`를 실행하면 "연결된 스위치가 없습니다. 본체 아래쪽 USB-C 포트에 데이터 케이블로 연결하고, 본체에서 PC로 복사 모드를 켜 주세요."를 보이고 종료 코드 1로 끝납니다. 시험용 기록 폴더에는 파일을 만들지 않았습니다.
- DMG: `make dmg`가 만든 DMG에는 `Pullshot.app`, `Applications` 바로 가기, `LICENSE`가 들어 있습니다.
  - 앱은 x86_64와 arm64를 함께 담았고 `codesign --verify --deep --strict`를 통과합니다.
  - ad-hoc 서명이라 Gatekeeper 평가(`spctl`)는 거부입니다. README가 안내하는 대로 처음 열 때 "그래도 열기"가 필요합니다.
  - DMG에서 바로 연 앱도 데모로 열렸고 quit 이벤트로 끝났습니다.

### 실기기로 남은 확인

- Step 1: 꽂은 뒤 "연결하는 중", "앨범을 읽는 중", 격자 순서로 저절로 바뀌는지, 게임 수와 캡처 수가 CLI `list`와 같은지, 처음 연결 질문을 "나중에"로 닫을 수 있는지 봅니다.
- Step 2: 실제 썸네일이 보이는 칸부터 채워지는지, 다시 열면 디스크 캐시에서 바로 뜨는지, 스페이스 미리보기가 사진과 동영상 모두 원본으로 열리는지 봅니다. 키보드 고르기도 이때 직접 눌러 봅니다.
- Step 3: 실제 가져오기 결과가 "저장 N개"인지, 다시 열었을 때 그 게임에 새 항목 점이 없는지, 받은 파일의 만든 날짜가 찍은 시각인지, 처음 연결 질문의 "폴더에서 찾기…"가 되는지 봅니다.
- Step 4: 고른 것을 가져온 파일 이름이 오른쪽 칸 미리보기와 같은지, "Finder에서 보기"가 그 파일들을 고르는지 봅니다.
