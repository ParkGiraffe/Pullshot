# Pullshot: 설계

작성일 2026-11-15. 앱 이름은 Pullshot(풀샷)이고, 이름을 정한 까닭은 9절에 있습니다.
처음에는 Tethersnap 리포의 `.claude/plans/new-app/`에서 썼고, Pullshot 리포를 만들며 이 자리로 옮겼습니다.

## 1. 요청과 이유

- 사용자는 Luminoid/Tethersnap에 게임별 모아보기 PR(#2)을 2026-11-08에 올렸고, 일주일이 지나도록 리뷰를 받지 못했습니다. 그래서 직접 주도해 관리할 앱을 따로 만들기로 했습니다.
- 이름도 리포도 새것입니다. Tethersnap의 포크가 아닙니다.
- 처음에는 Nintendo Switch 2와 Nintendo Switch(1)만 지원합니다.
- Tethersnap 코드를 가져오지 않고 처음부터 새로 짭니다. 쓰는 오픈소스는 Tethersnap과 같습니다.
- 화면은 Eagle과 Apple 사진을 섞은 2차 시안으로 정했습니다(사용자 승인 "ㄱㄱ 일단 ㄱ").
- 사용자는 캡처를 전부 받아 두지 않고, 글을 쓸 때 쓸 것만 그때그때 받습니다(사용자 답). 그래서 가져오기와 내보내기 모두 "Mac으로 옮김"으로 봅니다(6.3).

제가 파악한 쓰임새는 이렇습니다. 사용자는 스위치 캡처로 네이버 블로그에 게임 스토리 연재 글을 씁니다. 글 한 편에 쓸 캡처를 게임별로 고르고, 찍은 순서대로 번호를 붙여 올립니다. 게임 하나에 캡처가 2,626개까지 쌓여 있습니다. 첫 버전의 기능 우선순위는 이 쓰임새에서 나왔습니다.

## 2. 목표와 비목표

### 목표

- 스위치를 USB로 연결하고 "PC로 복사" 모드를 켜면, 드라이버 설치 없이 캡처 목록이 뜹니다.
- 캡처를 게임별로 보고 고를 수 있습니다. 게임 안에서는 최근 캡처가 먼저 보입니다.
- 아직 Mac으로 옮긴 적 없는 캡처를 새 항목으로 표시하고, 한 번에 가져올 수 있습니다.
- 고른 캡처를 찍은 순서대로 번호를 붙여 원하는 폴더로 내보냅니다.
- 파일은 스위치에 있는 그대로, 바이트 단위로 같게 저장합니다. 다시 인코딩하지 않습니다.
- 화면 문구는 한국어가 기본이고, 영어도 지원합니다.

### 비목표 (첫 버전에서 하지 않는 것)

- PS5, 카메라, 스팀덱, 메모리 카드, 임의 폴더 같은 다른 소스
- 스위치 SD 카드를 카드 리더로 읽기
- EXIF 날짜 고치기 같은 파일 안 메타데이터 쓰기
- 사진 편집, 태그, 별점 같은 보관함 관리
- 클라우드 업로드, 네이버 블로그에 바로 올리기
- 스위치에서 캡처 지우기. 스위치가 지우기 명령을 지원하지 않습니다(3절).

### 피할 일 (돌아가더라도 실패인 경우)

- Tethersnap 코드를 옮겨 적은 흔적이 남는 것
- 앱 이름, 아이콘, 화면이 닌텐도 상표나 닌텐도 화면을 흉내 내는 것
- 같은 캡처를 두 번 가져오거나, 이미 있는 파일을 덮어쓰는 것
- 가져오기나 내보내기가 중간에 끊겼을 때 반쪽 파일이 남는 것
- 게임 이름이 잘려서 비슷한 게임끼리 구별되지 않는 것(지금 Tethersnap 사이드바의 문제)
- 연결 상태 표시가 캡처 격자를 가리는 것(지금 Tethersnap의 문제)

## 3. 제약과 이미 아는 사실

### 스위치 쪽 사실

아래는 저작물이 아니라 사실이므로 그대로 써도 됩니다. 출처는 README의 감사의 글에 밝힙니다.

| 사실 | 출처 |
|---|---|
| USB ID는 Switch 2가 `057e:2061`, Switch가 `057e:201d`입니다 | Tethersnap README와 공개 코드 |
| PTP 1.00 응답기이고 MTP 확장이 없습니다. 기본 명령 10개(`0x1001` GetDeviceInfo ~ `0x100A` GetThumb)만 지원합니다 | Tethersnap README |
| 그래서 지우기(`0x100B` DeleteObject)를 쓸 수 없습니다 | 위 사실에서 따름 |
| 본체 아래쪽 USB-C 포트(독 아님)에 데이터 케이블로 연결하고, 본체 설정의 데이터 관리 메뉴에서 "USB 연결로 PC에 복사"를 켜야 합니다. 한국어 메뉴 이름은 실기기에서 확인합니다 | Tethersnap README |
| 저장소 전체 핸들을 한 번에 달라는 평면 질의를 거부합니다. 앨범 폴더를 따라 내려가며 목록을 만들어야 하고, 그 폴더 이름이 게임 이름입니다 | Tethersnap CHANGELOG 0.1.0 |
| 전송 모드에 다시 들어오면 세션 없는 GetDeviceInfo를 거부합니다. 세션을 연 뒤에 받으면 됩니다(펌웨어 22.5.0) | Tethersnap CHANGELOG 0.1.0 |
| 다른 프로세스가 연 세션이 남아 있으면 이후 요청을 모두 거부합니다. 세션 닫기, PTP 장치 리셋, USB 장치 리셋 순으로 풀어야 합니다 | Tethersnap CHANGELOG 0.1.0 |
| 저장소 ID가 세션마다 바뀝니다(`0x000F0001`, 다음엔 `0x00140001`). 핸들과 저장소 ID를 저장하면 안 됩니다 | Tethersnap CHANGELOG 0.1.0 |
| 저장소 용량을 모두 `0xFF…`(알 수 없음)로 보고합니다 | Tethersnap CHANGELOG 0.1.0 |
| 미리보기 앱이 켜져 있으면 macOS `ptpcamerad`가 PTP 인터페이스를 잡아, 인터페이스를 잡는(claim) 단계가 `0xE00002C9`(kIOReturnInternalError)로 실패합니다. 이미지 캡처나 사진 앱이 잡으면 `0xE00002C5`(kIOReturnExclusiveAccess)입니다 | 사용자가 2026-11-08 실기기에서 확인 |
| 펌웨어 22.5.0과 23.0.1에서 동작한 보고가 있습니다 | Tethersnap README |
| macOS에는 MTP 지원이 없고, OpenMTP와 Android File Transfer는 스위치 2에서 실패합니다 | Tethersnap README |

### 라이선스, 상표, 작업 방식

- Pullshot은 Tethersnap 코드를 쓰지 않으므로 Luminoid의 MIT 고지 의무가 없습니다.
- CLI가 링크하는 swift-argument-parser는 Apache-2.0입니다. 배포물에 `THIRD_PARTY_LICENSES.md`로 고지를 넣습니다.
- 앱 이름과 아이콘에 Nintendo, Switch, Joy-Con을 쓰지 않습니다. "Nintendo Switch 2 지원"처럼 설명에서만 쓰고, README와 정보 창에 닌텐도와 관계없다는 면책 문구를 넣습니다.
- 구현하는 동안 Tethersnap 리포의 `Sources/`와 `Tests/`를 열지 않습니다. 사람이 짤 때도, Claude나 하위 에이전트가 짤 때도 같습니다.
- 참고 자료는 PIMA 15740(ISO 15740) 표준, Apple IOUSBHost와 IOKit 문서, 위 사실 표, 그리고 Pullshot CLI로 실기기에서 직접 뜬 응답 덤프입니다.

### 환경

- 개발 맥은 macOS 26.5, Xcode 26.6, Swift 6.3입니다.
- 배포 대상은 macOS 15 이상입니다. macOS 26에서는 SwiftUI가 시스템 모양(Liquid Glass)을 알아서 입힙니다.
- 이 맥에는 Developer ID Application 인증서가 없습니다. 지금은 공증된 DMG를 만들 수 없습니다(8절).
- 테스트할 실기기는 사용자의 Switch 2입니다(펌웨어 23.0.1). Switch 1 실기기가 있는지는 확인하지 않았습니다.
- Tethersnap README는 Switch 1(시스템 버전 11.0 이상)도 같은 프로토콜이라고 적었습니다. 위 사실 표는 USB ID를 빼면 모두 Switch 2에서 나온 것이라, Switch 1의 인터페이스 종류, 평면 질의 거부 여부, CaptureDate와 GetThumb 동작은 확인되지 않았습니다.

## 4. 만드는 방법

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 필요한 코드만 가져오기 | 새 리포에 Tethersnap의 스위치 관련 코드만 옮겨 다듬습니다 | 실기기 검증이 끝난 코드가 그대로 남고, 며칠이면 첫 버전이 나옵니다 | LICENSE에 Luminoid 고지가 남고, 구조가 Tethersnap과 같습니다 |
| **B. 처음부터 새로 짜기 (선택)** | 표준 문서와 사실 표만 보고 새로 짭니다 | 저작권 고지가 사용자 것만 남고, 구조를 새로 정합니다 | PTP와 USB를 다시 짜고 실기기로 다시 검증해야 합니다 |
| C. 포크 유지 | GitHub 포크에서 이름만 바꿉니다 | 업스트림 수정을 가져오기 가장 쉽습니다 | "forked from" 표시와 원본 기록이 따라옵니다 |

사용자가 "아예 새로운, 나만의 앱"을 원해서 B를 골랐습니다. B의 위험인 실기기 버그는 3절의 사실 표로 상당 부분 미리 막습니다.

## 5. 사용자가 정한 것

- 새 이름, 새 리포, 사용자가 직접 관리합니다.
- 지원 기기는 Switch 2와 Switch 1입니다. 사용자에게 Switch 1 실기기가 없어서, 첫 버전에서 Switch 1은 "실험적 지원"으로 표시하고 써 본 사람의 제보로 확인합니다.
- 처음부터 새로 짭니다(B).
- 오픈소스는 Tethersnap과 같습니다. Apple 프레임워크(IOUSBHost, IOKit, SwiftUI, AppKit, ImageIO, AVFoundation, QuickLook), CLI용 swift-argument-parser, 개발 도구 SwiftLint와 SwiftFormat입니다. PTP 라이브러리(libgphoto2, libmtp)는 쓰지 않습니다.
- 화면은 2차 시안 `mockups/library-v2.html`입니다. PNG는 `mockups/v2-scene1-light.png`, `mockups/v2-scene2-dark.png`입니다. 레퍼런스 21장은 다른 앱의 화면이라 리포에 넣지 않고, 작성자의 맥(`~/Desktop/Coding/Tethersnap/.claude/plans/new-app/mockups/`)에만 둡니다.

## 6. 첫 버전 기능

5절 밖의 항목은 제 판단입니다. 사용자가 고칠 수 있습니다.

### 6.1 연결

- USB 연결과 분리를 감지해, 스위치가 꽂히면 저절로 엽니다. 두 대가 꽂히면 사이드바 위 기기 전환 단추로 고릅니다.
- Switch 1이 연결되면 기기 칸에 "실험적 지원"을 표시하고, 문제가 있으면 로그와 함께 이슈로 알려 달라는 안내를 둡니다.
- 연결 순서는 인터페이스 잡기, 세션 열기, 기기 정보 받기, 저장소 목록, 앨범 내려가기입니다. 3절의 재진입, 남은 세션 문제를 처리합니다.
- 다른 앱이 기기를 잡고 있으면(`0xE00002C5`, `0xE00002C9`) 일반 오류 대신 "미리보기, 이미지 캡처, 사진 앱을 닫아 주세요" 안내와 다시 시도 단추를 보여 줍니다.
- 아무 기기도 없으면 빈 화면에 스위치에서 PC로 복사 모드를 켜는 방법을 단계별로 보여 줍니다.
- 취소하면 받던 데이터를 끝까지 읽어 버리고 세션을 그대로 씁니다. 전송이 실패하면 어긋난 세션을 계속 쓰지 않고 버리되, 버린 세션도 닫아 둡니다. 스위치에 세션이 남으면 다음 연결이 USB 장치 리셋까지 가고 스위치가 PC로 복사 모드에서 나가기 때문입니다(2026-11-15 실기기 확인, `docs/hardware-notes.md`).

### 6.2 목록과 보기

- 앨범의 폴더 하나가 게임 하나입니다. 폴더 밖 항목은 "기타"로 묶습니다.
- 항목마다 파일 이름, 크기, 찍은 시각, 종류(사진, 영상)를 압니다. 찍은 시각은 ObjectInfo의 CaptureDate를 쓰고, 없으면 파일 이름의 숫자에서 읽습니다.
- 게임 목록은 최근 캡처 순입니다.
- 기본 보기는 최신순 한 격자이고, 날짜 보기(월 제목 아래 날별)로 바꿀 수 있습니다.
- 플레이별 보기(캡처 사이가 60분 넘게 비면 나누기)는 2026-11-15 사용자 결정으로 뺐습니다. 연재 글은 플레이가 아니라 스토리(화, 장, 미션) 단위로 나뉘기 때문입니다.
- 사진, 영상 필터와 썸네일 크기 막대가 있습니다.
- 썸네일은 GetThumb로 받습니다.
- 스페이스로 크게 봅니다. 원본을 임시 폴더에 받아 Quick Look으로 엽니다. Quick Look을 연 채 화살표를 누르면 격자처럼 한 칸이나 한 줄 넘기고 격자의 고른 칸도 따라갑니다(Finder 방식, 2026-11-17 사용자 결정). 넘길 때는 썸네일을 먼저 보이고 원본을 받으면 바꿉니다.
- 사이드바 아래 찾기 칸에서 게임 이름으로 좁힙니다.

### 6.3 새 항목과 가져오기

- 옮긴 기록을 Application Support에 저장합니다. 가져오기와 내보내기 모두 기록합니다. 열쇠는 기기 일련번호, 게임 폴더 이름, 파일 이름, 크기입니다. 핸들과 저장소 ID는 세션마다 바뀌므로 쓰지 않습니다. 일련번호가 세션마다 같은지는 실기기로 확인하고(7.1), 바뀐다면 열쇠에서 뺍니다.
- 처음 연결해 기록이 비어 있으면, 모든 캡처가 새 항목이 되지 않도록 한 번만 묻는 창을 띄웁니다. 지금까지 Tethersnap으로 받은 캡처를 기록에 넣기 위한 것입니다. 선택지는 세 가지입니다.
  - 폴더에서 찾기: 사용자가 고른 폴더 아래 어디에 있든, 파일 이름과 크기가 같은 캡처를 옮긴 것으로 기록합니다. 폴더 구조는 따지지 않습니다. Tethersnap의 기본 내보내기 폴더 `~/Pictures/Tethersnap`은 이 맥에 없으므로, 폴더는 사용자가 고릅니다.
  - 지금 있는 캡처를 모두 옮긴 것으로 표시합니다.
  - 모두 새 항목으로 둡니다.
- 새 항목은 옮긴 기록에 없는 항목, 곧 가져오기로도 내보내기로도 Mac에 옮긴 적이 없는 항목입니다. 글에 쓰려고 내보낸 캡처는 다음 연결부터 새 항목에서 빠집니다. 사이드바 "새 항목", 게임 줄의 주황 점, 격자의 주황 점이 모두 이 기준을 따릅니다.
- 가져오기는 `~/Pictures/Pullshot/<게임 이름>/<원래 파일 이름>`에 저장합니다. 위치는 설정에서 바꿉니다.
- 가져올 곳에 같은 이름과 크기의 파일이 이미 있으면 건너뛰고 기록에 남깁니다. 이름만 같고 크기가 다르면 번호를 붙여 따로 저장합니다.
- 저장한 파일의 만든 날짜와 수정 날짜를 찍은 시각으로 맞춥니다. 파일 안 메타데이터는 건드리지 않습니다.
- 오른쪽 칸의 "새 항목 N개 가져오기"는 지금 보는 게임의 새 항목을, 사이드바 "새 항목"에서는 전체 새 항목을 가져옵니다.

### 6.4 내보내기

- 고른 항목을 사용자가 고른 폴더로 내보냅니다. 내보낼 곳은 기준 폴더 하나(예: `사진/블로그`)를 기억하고, 기본으로 그 아래에 게임 이름 폴더를 만들어 넣습니다. "게임 이름 폴더 만들기"는 끌 수 있습니다. 그래서 다른 게임을 내보내도 앞 게임 폴더에 섞이지 않습니다.
- 파일 이름 규칙은 두 가지입니다. 원래 이름 그대로, 또는 찍은 순서대로 번호 붙이기(`001_20261114_211205.jpg`)입니다. 번호는 찍은 시각 오름차순이고, 자릿수는 개수에 맞춥니다(최소 3자리).
- 오른쪽 칸에 만들어질 파일 이름을 미리 보여 줍니다.
- 진행은 현재 파일과 전체 두 줄로 보여 주고, 취소할 수 있습니다.
- 임시 이름으로 쓰고 끝나면 이름을 바꿉니다. 실패하거나 취소하면 쓰던 파일을 지웁니다.
- 끝나면 Finder에서 보기 단추를 보여 줍니다.

### 6.5 화면

2차 시안을 따릅니다. 시안에 없는 세부는 만드는 사람이 정합니다. 시안의 플레이 묶음(플레이 제목, "이 플레이 고르기", "새로 찍음")은 빼고, 격자는 최신순으로 둡니다.

- 사이드바: 기기 전환 단추(연결 상태, 펌웨어 버전), 고정 항목(모든 항목, 새 항목, 영상, 최근 옮긴 항목), 게임 목록(최근 캡처 아이콘, 이름 두 줄까지, 개수, 새 항목 점), 맨 아래 찾기 칸
- 툴바: 사이드바 접기, 제목과 부제(기간, 사진 수, 영상 수), 썸네일 크기 막대, 보기 전환, 필터, 오른쪽 칸 접기
- 격자: 16:9 칸, 칸 사이 3pt, 새 항목 주황 점, 고른 칸은 강조색 테두리와 체크
- 오른쪽 칸: 고른 것이 없으면 게임 정보(항목, 크기, 처음과 마지막 찍은 날, 지난번 옮긴 날과 개수, 새 항목 수)와 가져오기 단추, 게임 전체 내보내기 단추. 고르면 겹친 묶음, 개수, 크기, 찍은 때, 내보낼 곳, 파일 이름 규칙, 파일 이름 미리보기, 내보내기 단추
- 라이트와 다크는 시스템을 따릅니다. 강조색은 보라(`#7A69FF` 근처)이고, 새 항목은 주황입니다.
- 연결 상태는 사이드바 기기 칸에만 둡니다. 격자 위에 떠 있는 상태 표시는 없습니다.
- 창이 좁으면 오른쪽 칸부터 접습니다.
- 시안의 툴바 돋보기는 빼고 사이드바 찾기 칸으로 대신합니다.

### 6.6 CLI

개발과 문제 찾기용입니다. swift-argument-parser로 만듭니다.

- `probe`: 기기 정보, 지원 명령, 저장소, 인터페이스를 출력합니다.
- `list`: 게임별 캡처 목록을 출력합니다.
- `pull`: 이름으로 고르거나 전부 받습니다.
- `dump`: 실기기 응답을 그대로 파일로 저장합니다. 이 덤프가 테스트 픽스처가 됩니다.
- `--verbose`는 USB 전송과 PTP 트랜잭션을 한 줄씩 출력합니다.

### 6.7 현지화와 로그

- 한국어가 기본이고 영어를 함께 둡니다. 두 언어 문자열의 키가 같은지 테스트로 확인합니다.
- String Catalog(`.xcstrings`)가 SwiftPM 빌드에서 컴파일되는지 먼저 확인하고, 안 되면 `.lproj/Localizable.strings`를 씁니다.
- 로그는 `os.Logger`와 `~/Library/Logs/Pullshot/` 파일에 함께 남깁니다. 파일 경로, 게임 이름, 파일 이름은 통합 로그에서 private로 가립니다. 도움말 메뉴에 로그 파일 보기를 둡니다.

## 7. 구조

- SwiftPM 패키지 하나에 타깃 세 개를 둡니다. 라이브러리(PTP, USB 전송, 모델, 옮긴 기록, 가져오기와 내보내기), SwiftUI 앱, CLI입니다.
- PTP 계층은 전송 프로토콜 뒤에 둡니다. 테스트는 가짜 전송에 실기기 덤프를 흘려 돌립니다.
- 앱 로직 중 테스트할 것(새 항목 판정, 파일 이름 규칙, 게임 순서)은 라이브러리에 둡니다.
- 테스트는 Swift Testing을 씁니다.
- 앱 번들은 Makefile이 조립하고 ad-hoc 서명합니다. Xcode 프로젝트를 둘지는 만드는 사람이 정합니다.
- SwiftLint와 SwiftFormat을 pre-commit 훅과 `make check`로 강제합니다.

### 7.1 실기기 검증

- 첫 단계는 CLI의 `probe`와 `dump`입니다. 앱 화면보다 먼저 만듭니다.
- 사용자가 스위치를 PC로 복사 모드로 켜 두고, 개발 초반에 30분 정도 실기기 작업을 한 번 몰아서 합니다. 그 전까지 PTP 계층은 표준 문서와 가짜 전송으로 짭니다.
- 그 30분 동안 덤프를 뜰 상황은 이렇습니다. 정상 연결, 목록, 썸네일, 사진과 영상 받기, 미리보기를 켠 상태, 이미지 캡처를 켠 상태, 전송 중 케이블 뽑기, PC로 복사 모드를 다시 켜기, CLI를 세션 중간에 강제로 끝낸 뒤 다시 연결하기입니다.
- 그때 함께 확인할 것은 이렇습니다. 기기 일련번호가 세션마다 같은지, 파일 이름 형식, 영상에도 GetThumb가 되는지, CaptureDate가 채워지는지, 한글 게임 폴더 이름이 제대로 오는지입니다.
- 실기기에서 나중에 확인할 것이 생기면 같은 방식으로 짧게 한 번 더 합니다.

## 9. 이름

이름은 **Pullshot(풀샷)**이고, 사용자가 제안했습니다. 기기에서 캡처를 끌어온다(pull)는 뜻이고, 한국어로 읽으면 사진 용어 "풀샷"과 소리가 같습니다.

| 항목 | 값 |
|---|---|
| 리포 | `ParkGiraffe/Pullshot` |
| 번들 ID | `com.parkgiraffe.Pullshot` |
| 가져올 곳 기본값 | `~/Pictures/Pullshot/<게임 이름>/` |
| 로그 | `~/Library/Logs/Pullshot/` |
| CLI 명령 | `pullshot` |

- Nintendo, Switch, Joy-Con 같은 상표가 들어가지 않습니다.
- 2026-11-15에 찾아보니 같은 이름의 Mac 앱은 없었습니다. GitHub에는 git pull을 자동화하는 작은 CLI(`MarchanoGG/Pullshot`, 별 2개)와 설명 없는 2022년 리포 두 개가 있습니다. 용도가 달라 헷갈릴 일은 적습니다.
- 처음 후보였던 Playroll, Savepoint, Kirin Album은 쓰지 않습니다.
